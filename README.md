# BTC Monitor: единая картина сигналов

Собирает рыночные и макро-метрики из бесплатных источников, переводит каждую в сигнал от −1 до +1,
сводит их в индекс от −100 до +100, показывает всё на одном экране с живой ценой BTC
и присылает уведомления о важных изменениях. Индекс описывает текущее состояние рынка и не предсказывает цену.

Как читать экран и что означает каждый сигнал — в [FEATURES.md](FEATURES.md).

## Структура проекта

```
btc_monitor/
├── config.py          # настройки: веса, пороги, интервал, рынки Polymarket
├── sources.py         # сбор данных из API
├── scoring.py         # сигналы, группы, итоговый индекс, чек-лист импульса
├── alerts.py          # правила уведомлений и отправка в Telegram
├── storage.py         # история замеров в SQLite
├── monitor.py         # сбор данных по расписанию
├── app.py             # веб-экран: главная страница и «Подробнее», живая цена
├── presentation.py    # тексты, расшифровки и события для веб-экрана
├── requirements.txt
├── FEATURES.md        # как читать экран и сигналы
├── .env.example       # шаблон секретов (копируется в .env)
└── deploy/            # systemd-юниты и скрипт установки на сервер
```

Система состоит из двух процессов. `monitor.py` раз в 15 минут собирает данные и пишет их в `btc_monitor.sqlite`.
`app.py` читает эту базу и показывает экран. Вся история хранится в базе, поэтому экран можно
перезапускать и обновлять, ничего не теряя.

## 1. Локальный запуск на macOS

Нужен Python 3.10 или новее (`python3 --version`). Если версия старше, установите новую: `brew install python@3.12`.

Первая установка:

```bash
cd ~/src
unzip ~/Downloads/btc_monitor.zip
cd btc_monitor

python3 -m venv .venv            # создать окружение (один раз)
source .venv/bin/activate        # активировать (в каждом новом окне терминала)
pip install --upgrade pip
pip install -r requirements.txt

cp .env.example .env             # ключ FRED и токены Telegram
open -e .env
```

После активации в начале строки терминала появится `(.venv)`. Выйти из окружения: `deactivate`.

Проверочный прогон сбора данных:

```bash
python monitor.py --once
```

Постоянная работа — два окна терминала, в каждом сначала `cd ~/src/btc_monitor && source .venv/bin/activate`:

```bash
# окно 1: сбор данных раз в 15 минут
python monitor.py

# окно 2: веб-экран; caffeinate не даёт Mac уснуть
caffeinate -dims python app.py
```

`app.py` напечатает адрес вида `http://192.168.1.23:8600`. На самом Mac можно открыть `http://localhost:8600`.
Если macOS спросит, разрешить ли Python входящие подключения, нажмите «Разрешить».

### Обновление на Mac из нового архива

Браузер не перезаписывает уже скачанный файл, а сохраняет новый под другим именем:
`btc_monitor 2.zip`, `btc_monitor (1).zip` и так далее. Поэтому распаковывайте самый свежий архив, а не первый по имени:

```bash
cd ~/src
ls -lt ~/Downloads/btc_monitor*.zip | head -3      # самый новый — первый в списке
unzip -o "$(ls -t ~/Downloads/btc_monitor*.zip | head -1)"
cd btc_monitor
source .venv/bin/activate
pip install -r requirements.txt
git status                                          # что изменилось
```

После распаковки остановите `monitor.py` и `app.py` (Ctrl+C) и запустите заново: Python не подхватывает
изменённый код на лету. Ваши `.env`, `.venv` и база данных при распаковке не затираются, их нет в архиве.

Распаковка не удаляет файлы, которых больше нет в проекте. Если в описании изменений сказано, что файл удалён,
уберите его через git: `git rm имя_файла`. Чтобы не путаться, старые архивы из «Загрузок» можно удалять:
`rm ~/Downloads/btc_monitor*.zip`.

## 2. Экран на iPad (iOS 6 и новее)

Страница специально сделана без современных веб-технологий и работает даже на iPad с iOS 6.

1. iPad и Mac должны быть в одной сети Wi-Fi. Откройте в Safari адрес, который напечатал `app.py`.
2. «Поделиться» → «На экран Домой». Иконка откроет страницу на весь экран, без панелей Safari.
3. «Настройки» → «Основные» → «Автоблокировка» → «Никогда».
4. Чтобы iPad не уходил со страницы, включите «Гид-доступ»: «Настройки» → «Основные» →
   «Универсальный доступ» → «Гид-доступ», затем откройте страницу и трижды нажмите кнопку «Домой».
5. Держите iPad на зарядке.

Нажатие на плашку с изменением цены переключает проценты и доллары. Нажатие на карточку индекса
открывает «Подробнее»; через 3 минуты без касаний экран сам вернётся на главную.
Если Mac выключится, на экране появится «нет связи», а после его возвращения страница обновится сама.

Экран работает без пароля, поэтому открывайте его наружу только в домашней сети.

## 3. Публикация в Git

```bash
cd ~/src/btc_monitor
git add .
git commit -m "описание изменений"
git push
```

Файлы `.env`, `.venv/`, база `*.sqlite` и кэш FRED исключены через `.gitignore` и в репозиторий не попадут.
Перед коммитом полезно посмотреть `git status`.

## 4. Развёртывание на сервере (Ubuntu / Debian)

```bash
sudo apt update && sudo apt install -y python3 python3-venv git

cd ~
git clone git@github.com:<ваш-логин>/<репозиторий>.git btc_monitor
cd btc_monitor

cp .env.example .env && nano .env
bash deploy/install.sh
```

Скрипт создаст `.venv`, установит зависимости и запустит два systemd-сервиса:
`btc-monitor` (сбор данных) и `btc-web` (веб-экран на порту 8600). Оба перезапускаются при сбое и после перезагрузки.
Если на сервере раньше был установлен старый `btc-dashboard`, скрипт его отключит.

Для `git clone` по SSH на сервере нужен ключ с доступом к репозиторию
(проще всего — deploy key в настройках репозитория, только чтение).

### Доступ к экрану на сервере

По умолчанию экран слушает только `127.0.0.1:8600` и снаружи не виден: в нём нет авторизации.
Открывайте его через SSH-туннель с Mac:

```bash
ssh -L 8600:localhost:8600 <пользователь>@<адрес-сервера>
```

и затем в браузере `http://localhost:8600`. Если сервер стоит у вас дома и экран нужен в локальной сети
(например, для iPad), установите с `WEB_HOST=0.0.0.0 bash deploy/install.sh`.
Для доступа из интернета поставьте перед ним nginx с паролем; учтите, что iOS 6 не умеет современный HTTPS.

### Управление сервисами

```bash
sudo systemctl status btc-monitor btc-web
journalctl -u btc-monitor -f            # живые логи
sudo systemctl restart btc-monitor btc-web
sudo systemctl stop btc-monitor btc-web
```

### Обновление после изменений

```bash
cd ~/btc_monitor
git pull
.venv/bin/pip install -r requirements.txt
sudo systemctl restart btc-monitor btc-web
```

Если обновление добавило или переименовало сервисы, вместо перезапуска выполните `bash deploy/install.sh` ещё раз.

## Что отслеживается

| Группа (вес) | Метрика | Источник |
|---|---|---|
| Потоки денег (40%) | Потоки в спотовые BTC-ETF | Farside (или ручной CSV) |
| | Coinbase Premium | Coinbase + Binance |
| | Капитализация стейблкоинов | DefiLlama |
| Плечо и позиции (20%) | Open interest, funding, их связка с ценой | Binance Futures |
| Тренд (15%) | Цена против MA50/MA200, объём | Binance |
| Макро (25%) | DXY, доходность 10Y, Nasdaq, VIX, нефть, USD/JPY | Yahoo Finance |
| | Чистая ликвидность ФРС (WALCL − TGA − RRP) | FRED |
| Без влияния на индекс | DVOL (ожидаемая волатильность), индекс страха и жадности, Polymarket | Deribit, alternative.me, Polymarket |

Отдельно проверяется чек-лист «подтверждённого импульса»: приток в ETF 3+ дня подряд, положительный
Coinbase Premium, растущий OI при неперегретом funding, цена выше MA50 на повышенном объёме.

## Настройка

`config.py`: веса групп, пороги сигналов, границы режимов и slug рынков Polymarket
(берётся из адреса `polymarket.com/event/<slug>`). `.env`: токены Telegram, необязательный ключ FRED и интервал опроса.

## Ограничения

- Binance недоступен с серверов в некоторых странах, в том числе в США и у части облачных провайдеров.
  Выбирайте сервер в Европе или проверьте доступ командой
  `curl -s https://fapi.binance.com/fapi/v1/ping` (должно вернуть `{}`).
- Farside иногда блокирует автоматические запросы, особенно с IP дата-центров. Тогда положите рядом
  файл `etf_flows_manual.csv` с колонками `date,total_musd` или подключите платный API.
- Ончейн-данные о резервах бирж и китовых кошельках (CryptoQuant, Glassnode, Arkham) в бесплатном виде
  почти не доступны через API, поэтому здесь не реализованы.
- FRED иногда отвечает медленно. Монитор делает три попытки, а при неудаче использует последнее
  сохранённое значение (данные недельные, так что это безопасно). Бесплатный ключ `FRED_API_KEY`
  в `.env` делает загрузку быстрее и стабильнее.
- API-ключи бирж не нужны: все данные берутся из публичных эндпоинтов.
- Пороги и веса — стартовые значения, а не откалиброванная модель.

## Частые проблемы

| Сообщение | Причина и решение |
|---|---|
| `ModuleNotFoundError: No module named 'requests'` (или другой модуль) | Не активировано окружение. Выполните `source .venv/bin/activate` в этом окне терминала; если не помогло — `pip install -r requirements.txt` |
| `ImportError: cannot import name ... from ...` | Файлы проекта из разных версий: часть обновилась, часть нет. Распакуйте самый свежий архив целиком (см. «Обновление на Mac из нового архива») и перезапустите оба процесса |
| `Address already in use` при запуске `app.py` | Экран уже запущен в другом окне. Остановите его (Ctrl+C) или найдите процесс: `lsof -i :8600` |
| На экране «данные устарели» | Не работает `monitor.py`. Проверьте окно, где он запущен, или `journalctl -u btc-monitor -f` на сервере |
| На iPad «нет связи» | Mac уснул, выключен или в другой сети. Запускайте `app.py` через `caffeinate`, проверьте Wi-Fi |
| В «Источниках данных» ошибка FRED | Нет ключа или FRED временно недоступен. Добавьте `FRED_API_KEY` в `.env`; при сбое используется последнее сохранённое значение |
